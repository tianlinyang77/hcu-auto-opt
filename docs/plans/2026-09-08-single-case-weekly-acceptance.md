# 本周固定案例验收计划

截止目标：2026-09-11。维护方式：单人串行，#126 跟踪执行，#102 跟踪当期就绪，#46 跟踪操作入口。
这是交付计划，不是性能收益承诺；当前未完成实机闭环，也没有新窗口授权。

## 本周交付物

1. 一个固定目标和工作负载，固定源码/镜像/输入及候选数量；沿用已审查的热点，禁止临时扩展多模型、多节点或自动发布。
2. 可复跑命令：候选、构建/制品、执行、失败或成功证据、独立读取；参数与证据目录明确，不依赖维护者在终端手工改状态。
3. 页面可查看该次 Run 的实际状态、用量、候选差异和证据；明确区分模拟模型、真实模型、CPU 测试与实机测量。不能拿旧展示 Run 充当本周真实案例。
4. 一页验收记录：固定 commit、命令、环境、输入/输出 Hash、结果、失败处理、残留资源检查与尚未完成项。人工签署单独进行。

## 顺序与停止点

- 首先收口 #148 的 M1/Formal 输入、结果、故障计量桥接和 CI，不改现有独立测量/判决边界。
- 随后把同一组冻结部署输入接入完整生命周期，完成 CPU 整链成功、部分失败、预算保留与重复执行防护检查。D 摘要独立复算和部分成员复用检测仍需补齐，不能仅依赖生产端摘要。
- 准备本周实机单轮所需的精确窗口、Family/Plan/预算与 Target Lock，获得当期授权后在指定设备进行；不停止其他人的工作负载，不复用历史临时放行。
- 最后展示新 Run 的页面和可复跑命令，报告实际测得的结论。未测到加速也如实交付，不将工程通过写成性能通过。

## 本周不扩展

不增加多用户 SSO、微服务、全自动发布、重编系统库、多节点、多模型搜索或更多 Agent 调度策略。
Skills 继续仅作候选知识输入，不承担测量、预算、签署或发布权限。

## 外部依赖

当期实机窗口尚待项目所有者确认；最终执行仍要绑定精确 Candidate Family、Profile、预算和恢复范围。
若窗口未到位，交付可以先完成 CPU 可运行工程版本，但必须明确标注“未完成实机验收”，不得替代本周性能结果。
