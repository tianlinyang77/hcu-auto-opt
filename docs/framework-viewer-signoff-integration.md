# 结果页签核接入边界（实现待审，真实签核未执行）

## 当前成果

只读结果页已绑定具体任务、最新评测和最新 EvidenceBundle；旧证据或其他任务的证据
不能使新评测显示为可签核。`review_evidence_id` 是展示绑定信息，不是签核授权。
默认页面没有写操作；可选签核部署须显式启用。真实任务仍等待人工确认，不能据此声称 Stage0 或性能验收通过。

## 复用现有协议

继续使用 `POST /v1/framework-smoke/tasks/{task_id}/signoff` 和
`FrameworkSmokeSignoffRequest`，不新增平行状态机、不在浏览器直接写数据库。
现有 Repository 已处理任务状态、通过的评测、最新证据、并发和幂等检查。
但请求中的 `actor` 是调用方传入的字符串，不等于已经验证的签署身份。

## 下一实现切片

1. 默认保留只读部署。签核是独立、显式启用的服务能力，不使用当前只读数据库连接。
2. 独立按任务签核凭据绑定预配置签署人；与页面访问凭据、实例控制凭据、模型密钥分离。
   服务端派生 actor，不能接受浏览器任意填写的签署身份。这不是企业 SSO。
3. 人工确认展示任务、评测、最新证据 ID、批准/拒绝、理由，以及本次仅为框架 Smoke 的范围。
   用户点击前不发送写请求；读取或刷新页面不能隐式签署。
4. 可信写入口先认证与核对任务授权，再调用原签核协议；原 API 不得留下可以绕过
   身份校验的外露写路径。接入前需完成部署网络和现有身份机制检查。
5. 提交绑定 evidence_bundle_id 和稳定的 idempotency_key；超时先查询结果，
   不换 key 盲重试。证据更新返回冲突，要求重新阅读，不能静默改绑新证据。
6. 成功后读取原持久化签核结果与任务状态。签署 Framework Smoke 不得解除
   Stage0、候选激活、性能判决或发布闸门。

## 验证要求

- 无凭据、只读凭据、控制凭据、其他任务签核凭据均不能写入。
- 浏览器伪造 actor、过期凭据、CSRF/跨来源请求均拒绝；凭据不进入 URL、日志或 Git。
- 同一请求重放只产生一次决定；不同载荷复用 key 返回冲突。
- 过期证据、并发提交、已经结束的任务由原状态机拒绝。
- 数据库集成只用随机隔离测试 schema，不清空共享表、不用真实待签任务做测试。
- 真实任务最后一格必须由用户明确确认；本文件和“继续开发”都不是验收签字。

## 本地签核切片

已增加独立凭据发放/到期/撤销、可选部署接线、两步人工确认、幂等回读与冲突处理。
本次 PostgreSQL 测试使用随机 `signoff_test_<uuid>` schema，通过原 Fake 工作流产生测试证据，
再验证真实数据库事务；它不代表真实 HCU、正式签字或优化收益。

操作方启用签核时：

1. 在经过检查的 viewer 配置中加入 `"signing": {"actor": "<指定签署人>", "ttl_seconds": 1800}`。
   不把 DSN、凭据或模型密钥写入 JSON。现有默认示例维持只读。
2. 通过进程环境分别提供只读连接输入 `HCUOPT_VIEWER_DATABASE_URL`、显式签核连接输入
   `HCUOPT_SIGNING_DATABASE_URL`，必须是同一目标数据库，不得把已有读连接改为可写。
3. 启动 `python -m hcuopt framework-viewer serve <config.json> --signing-dsn-env HCUOPT_SIGNING_DATABASE_URL`。
   保持127.0.0.1绑定；服务生成新的私有实例目录、访问/控制/签核三个独立凭据文件。
4. 用户用 access-key 查看，再用 signing-key 验证指定签署人。核对被冻结的任务、评测、证据、
   决定和理由，点击“我已核对，确认提交”才写原签核 API。签核结果从数据库回读。
5. 不再需要签核时运行 `python -m hcuopt framework-viewer revoke-signing <instance-directory>`；
   已发放签核凭据立即停止接受新请求，删除签核文件，查看能力保留。
6. `framework-viewer stop <instance-directory>` 撤销所有实例能力、等待请求退出、清理凭据，
   仅关闭该实例拥有的隧道。系统崩溃/强杀可能留下本地文件，旧进程停止后不得复用旧签核凭据。

凭据代表持有能力，不是企业 SSO；查看凭据、控制凭据和模型密钥都不能签核。
到期/撤销后不自动续期，操作方必须显式重启签核实例发放新凭据；未知提交可用同签署人新凭据
查询、恢复原请求，但不能更换证据或伪造签署人。凭据不进入 URL、Git、日志或浏览器持久存储。
