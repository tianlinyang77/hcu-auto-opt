# Web Scripted 启动接线

计划预览现在可以提交已有 `POST /v1/operator/round-plans/{preview_id}:start` 接口。
操作者在既有计划页选择环境、工作负载、热点、候选和测量预设，核对预算和警告，填写
操作者并明确勾选确认后，创建 Scripted 演练轮次。预算继续由已登记 Measurement Profile
提供，页面不生成新的测量策略。

启动响应显示控制面状态与 Round ID，并可直接打开启动审计。`finalized` 只表示轮次创建
完成，不表示执行、正确性、性能评估或签核已经完成。此入口不调用 Formal 启动 API。

## 重试规则

提交前冻结 Preview ID、Plan Hash、操作者、服务身份、警告确认和幂等键。同一页面会话
中，网络失败重试复用完全相同的请求；并发点击共享同一请求。回执必须匹配冻结身份。
离开并重新打开同一 Preview 时，页面会话仍保留冻结请求。

请求在发送前写入同源 sessionStorage，只保存冻结的 Scripted 请求字段，不保存密钥。
保存失败时不发送启动请求。刷新后首页显示恢复入口，由操作者确认后原样重发，后端按
同一幂等键恢复。响应丢失时不生成新编号。存储损坏时阻止继续提交，需要先核查记录。
关闭标签页、清除浏览器数据或换浏览器不在此恢复范围内；应保留请求编号交给控制面核查。

## 部署范围

- Demo 模式不提交启动请求。
- 页面需要由同源 Operator API 部署，且后端已登记有效的 Scripted Profile、候选和权限引用。
- 现有 endpoint-console 仍是只读结果入口，不转发此写接口。
- 操作者字段为 Scripted 审计标签，不是登录身份，也不能用于授权正式硬件执行。
- 正式启动需下一切片接入已有 Formal 授权协议；不能把这里的按钮直接改为 Formal。

自动化验证覆盖前端请求/回执、存储失败、刷新恢复，以及前端 JavaScript 经真实 HTTP
访问 FastAPI 的响应丢失重试。HTTP 测试使用 synthetic 内存仓库；不替代 PostgreSQL
部署联验、浏览器点击验收或真实 HCU 验收。
