# MVP 范围与验收

## 固定边界

- 硬件：1 种 HCU，固定服务器与拓扑。
- 软件：1 个 DTK 版本、1 个推理框架版本、1 个模型版本。
- Workload：冻结请求集、Shape 分布、并发和 SLO。
- 优化：配置 + 可热补丁 Triton / 独立 HIP 制品。
- 发布：生成 Release Candidate 和签核材料，不做无人值守生产发布。

## 第一条业务链

RMSNorm 仅作为正确性与 Artifact 流转夹具。另准备一个人为降速的大信号夹具验证测量和 E2E 能看到已知差异。

真正的首个优化目标必须由以下证据选择：

```text
真实 Profiling
→ 调用路径确认
→ Amdahl 机会评分
→ 上游查重
→ 可补丁性判断
```

## MVP 验收

系统能在固定环境中自动完成：

1. 读取通过 Stage 0 的环境能力声明；
2. 冻结一个 Baseline Epoch；
3. 从真实 Workload 产生 Hotspot；
4. 生成至少两个不可变候选；
5. 隔离构建并记录 Hash/SBOM；
6. 完成 Kernel 正确性、性能和 Holdout；
7. 在轮次 Barrier 进行多候选统计校正；
8. 完成模型正确性和 ABBA E2E；
9. 输出可复现实验与人工签核材料；
10. Worker 故障后能够 Fencing 并恢复或隔离机器。

## 阶段二

- 整仓重编译与 `_C.so`。
- 系统库、驱动、通信库的节点级变更。
- 多机调度和生产灰度自动化。
- 图融合、内存、CPU 调度和通信优化轨道。
